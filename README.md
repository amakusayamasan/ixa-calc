# IXA 部隊計算

戦国IXAの攻撃部隊・防御部隊の素火力を計算するツールです(部隊計算画面の「部隊タイプ」で切り替え)。
武将・スキル・兵種・バフのマスタは Firebase(Firestore)に保存し、管理者だけが登録・編集できます。
サイトは GitHub Pages で公開します。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `index.html` | 画面の骨組み(HTML)。CSS と JS を読み込むだけ |
| `css/style.css` | 見た目 |
| `js/core.js` | 定数・部隊タイプ(攻撃部隊・防御部隊で使う値の違い)・共有の状態・どこからでも使う小さな道具 |
| `js/fields.js` | マスタの項目の定義(入力項目・選択肢・並び順) |
| `js/skills.js` | **スキルのルール**(係数の掛け方、攻撃or防御、特殊効果のチェック、模倣、無尽の倍率、重複上限、保存するときの形) |
| `js/cards.js` | **武将と初期スキルのルール**(武将のTR、初期スキルの効果、無尽部隊、部隊長限定、バフ、保存するときの形) |
| `js/unit.js` | **部隊内で数えるもの**(同じスキルの数、Xスキルの数、飛翔の数、部隊移動速度、重複上限で外す枠) |
| `js/calc.js` | 火力の計算と、武将ごとの内訳 |
| `js/calc-view.js` | 部隊計算画面(編成の保存、武将・スキルの候補、バフの選択) |
| `js/teams.js` | 保存した部隊(部隊名を付けてこの端末に保存・読み込み・削除。攻撃・防御別、保存時の最大火力つき) |
| `js/master.js` | マスタ管理画面(一覧の列、編集パネル、保存) |
| `js/excel.js` | Excel の取り込み・ダウンロード |
| `js/admin.js` | 管理者の書き込み(最終更新者・変更履歴)、初期データ投入、ログイン表示 |
| `js/main.js` | 画面の切り替えと起動(Firebase への接続・マスタの読み込み) |
| `firebase-config.js` | Firebase の接続設定 |
| `firestore.rules` | データを守るセキュリティルール(Firebase に貼り付ける) |
| `seed/master.json` | 初期データ |
| `tests/` | 回帰テスト(下記) |

JS は上の表の順に読み込みます(`index.html` の `<script>` の順)。ルールを変えるときは、まず `js/skills.js`・`js/cards.js`・`js/unit.js` を見てください。
各ファイルの2行目に「使うファイル」を書いています。`node tests/deps.js` で、どのファイルのどの名前を使っているかを一覧できます(`--write` で2行目を書き直します)。
JS や CSS を変えたら、`index.html` の `?v=…` の番号も変えてください(ブラウザに古いファイルが残らないようにするため)。

### 回帰テスト

計算や画面の動きが変わっていないかを確かめるテストです。Firebase と SheetJS は模擬版(`tests/stub.js`・`tests/fakexlsx.js`)に差し替えて動かします(Node.js と Playwright が必要)。

```
python3 -m http.server 8765        # リポジトリのフォルダで
node tests/regress.js > after.json # 別のターミナルで
```

変更の前と後で出力(`after.json`)が同じなら、計算結果・表示・保存されるデータは変わっていません。

`node tests/rules.js` は、飛翔の数・部隊移動速度・重複上限で外れた初期スキルの計算を、決まった期待値と比べます(「すべてOK」と出れば合格)。

| `index.html` | ツール本体(計算画面・マスタ管理) |

| `firestore.rules` | データを守るセキュリティルール(手順3で Firebase に貼り付ける) |

## 公開までの手順

### 1. GitHub Pages を有効にする

1. このリポジトリの **Settings → Pages** を開く
2. **Source** を「Deploy from a branch」、**Branch** を `main` / `/ (root)` にして **Save**
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けるようになります
   (この時点では「Firebase の設定がまだです」と表示されれば正常です)

### 2. Firebase プロジェクトを作り、設定を書き込む

1. https://console.firebase.google.com/ を開き、**プロジェクトを作成**(名前は例:`ixa-calc`。Google アナリティクスはオフで構いません)
2. プロジェクトのトップで **ウェブアプリを追加**(`</>` アイコン)。名前は任意、Firebase Hosting のチェックは不要
3. 表示される `firebaseConfig` の値を、`firebase-config.js` の該当箇所にそのままコピーしてコミット

### 3. データベースとログインを有効にする

1. **構築 → Firestore Database → データベースを作成**
   - ロケーション:`asia-northeast1(東京)`
   - 「本番環境モード」で作成
2. Firestore の **ルール** タブを開き、`firestore.rules` の中身を全部貼り付けて **公開**
3. **構築 → Authentication → 始める → Sign-in method** で **Google** を有効にする
4. **Authentication → 設定 → 承認済みドメイン** に `<ユーザー名>.github.io` を追加

### 4. 自分を管理者に登録する

1. 公開したサイトを開き、右上の **管理者ログイン** から Google アカウントでログイン
2. 「管理者として登録されていません」という案内と **ユーザーID** が表示されるので、コピーする
3. Firebase コンソールの **Firestore Database → データ** で
   - **コレクションを開始** → コレクションID:`admins`
   - **ドキュメントID**:コピーしたユーザーID
   - フィールド `name`(文字列)に **表示名** を入れる(例:`name` = `天草`)。マスタを保存すると「最終更新者」として記録され、サイトを開いた全員に表示されます。表示名がないと保存できません
4. サイトを再読み込みすると、右上が「管理者」になります

### 5. 初期データを入れる

管理者でログインした状態で **マスタ管理** を開くと「初期データを投入」ボタンが出ます。
押すと Claude 版で登録していたマスタがそのまま入ります。
以降は Excel(武将データ・スキルデータのシート)からの取り込みや、画面での編集で更新できます。

### 6. みんなに共有する

サイトの URL を共有するだけです。ログインしなくても計算とマスタの閲覧ができます。
組んだ編成は、それぞれのブラウザに保存されます。

## よくある質問

**Q. `firebase-config.js` の API キーを GitHub に公開して大丈夫?**
A. 大丈夫です。この値はサイトを開いた全員のブラウザに送られるもので、秘密の鍵ではありません。
データの書き込みは `firestore.rules` で「admins に登録された人だけ」に制限しています。

**Q. 管理者を増やしたい**
A. その人にサイトでログインしてもらい、表示されたユーザーIDを `admins` コレクションに追加してください。フィールド `name` に表示名も入れてください。

**Q. 料金は?**
A. Firebase の無料プラン(Spark)で動きます。読み込みは1日5万回まで無料で、1回開くと約20回読み込むので、1日2,000回程度開いても無料枠内です。

**Q. マスタのバックアップは?**
A. Firestore コンソールから確認できます。Excel を元データとして持ち続け、必要なら「Excelから取り込み」で作り直せます。
